Complete Workflow for Melodic Justice

Real World Performance

Actor performs the movement/action in front of two cameras positioned 45-90° apart.

Setup Requirements:
  • 2 USB webcams (720p minimum, 1080p recommended)
  • Good even lighting, no harsh shadows
  • Plain background contrasting with actor
  • Fitted clothing (not baggy or reflective)
  • Full body visible in BOTH cameras
📹 Output: Real-time video feeds from Camera 0 and Camera 1
↓
1

Capture Motion Data

mocap_recorder.py

Python application records from both cameras simultaneously. MediaPipe detects 33 body landmarks per camera. System triangulates 3D positions from the two 2D views, creating true 3D motion data.

Process:
  • Run: python mocap_recorder.py
  • Position yourself visible in both camera windows
  • Press SPACE to start recording (red dot appears)
  • Perform your action
  • Press SPACE to stop recording
  • Data automatically saved with timestamp
💾 Output: take_YYYYMMDD_HHMMSS.json + .bvh files
↓
2

Import to Blender

mocap_rigify_retarget.py (Blender Addon)

Blender addon reads the mocap JSON data and creates an intermediate armature. The mocap skeleton structure is built from MediaPipe landmarks, and all frame data is applied as keyframed animation.

Process:
  • In Blender: File → Import → Mocap JSON
  • Select your take_*.json file
  • Addon creates "MocapArmature" with animation
  • Timeline shows frame range
  • Press SPACE to preview motion
🦴 Output: Animated mocap armature in Blender scene
↓
3

Retarget to Rigify

rigify_constraint_retarget.py

Maps mocap skeleton bones to JaxRigify CONTROL bones (not deformation bones!). Uses bone constraints for stable, preview-able retargeting. Once verified, bakes to keyframes and removes constraints.

Process:
  • Open script in Blender Text Editor
  • Edit armature names (lines 133-134)
  • Run script → sets up constraints
  • Preview animation (press SPACE)
  • Run: bake_animation() to freeze
  • Run: remove_constraints() to clean up
✨ Output: JaxRigify with baked animation on control bones
↓
4

Refine Animation

Manual work in Blender

Polish the mocap-driven animation. Adjust timing in Graph Editor, add facial animation manually (jaw, eyes, brows), refine hand poses, lock feet to ground, and add secondary motion for life.

Refinement Tasks:
  • Timing: Speed up/slow down sections, add ease in/out
  • Face: Animate jaw, eyes, eyebrows (mocap doesn't capture these)
  • Hands: Key finger poses at important moments
  • Feet: Add Floor constraints to prevent sliding
  • Secondary: Add shoulder overlap, spine settle, weight shifts
🎭 Output: Final polished animation ready for rendering!

🦴 Understanding Rigify Structure

Critical: Rigify has THREE layers of bones. You must animate the CONTROL bones, not the deformation bones!

Layer 1: CONTROL BONES (What You Animate)

These are the bones you see and manipulate. They have widgets (shapes) you can select.

Examples: torso, chest, head, hand_ik.L, hand_ik.R, foot_ik.L, foot_ik.R, upper_arm_fk.L, forearm_fk.L, etc.
Layer 2: MECHANISM BONES (Automatic, Hidden)

Hidden bones (MCH-*) that handle IK solving and constraint systems. Driven by control bones through constraints.

Examples: MCH-upper_arm_ik_target.L, MCH-thigh_parent.L, etc.
Layer 3: DEFORMATION BONES (What Moves The Mesh)

These bones (DEF-*) actually deform the JaxBody5 mesh. They're driven by mechanism bones. Never animate these directly!

Examples: DEF-spine, DEF-spine.001, DEF-upper_arm.L, DEF-forearm.L, etc.
⚠️ Common Mistake: Trying to retarget to DEF- bones directly. This breaks the rig! Always target control bones instead.

💡 Key Concepts

Why Dual Cameras?

A single camera only captures 2D positions (x, y). Adding a second camera at an angle allows triangulation - mathematically calculating the true 3D position (x, y, z) by comparing where the same point appears in both camera views. This is essential for accurate depth (Z-axis) and rotation data.

IK vs FK - Which to Use?

IK (Inverse Kinematics): You move the hand, and the arm follows automatically. Best for mocap because you're controlling endpoints (hand/foot positions).

FK (Forward Kinematics): You rotate each joint individually (shoulder, elbow, wrist). Better for stylized animation where you want precise rotation control.

For mocap: Use IK mode (set IK/FK switches to 1.0 on JaxRigify).

Why Constraints Instead of Direct Keyframing?

Constraints allow you to preview the retargeting in real-time before committing. If something looks wrong, you can adjust the constraint settings and immediately see the result. Once you're happy, you "bake" the animation to keyframes. This is much more stable and flexible than trying to copy keyframes frame-by-frame.

Why Previous Attempts Failed

Flat triangulation: Improper coordinate system conversion made dual-camera data look 2D from certain angles.

Retargeting failures: You were likely targeting DEF- bones (deformation) instead of control bones, or using wrong coordinate spaces in constraints.

Single camera issues: Without depth data, torso rotation was just guessed by MediaPipe, leading to incorrect rotations.
